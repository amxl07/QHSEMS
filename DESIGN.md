# Design System: QHSEMS Consultancy, Solutions & Training LLP

## Overview

**Creative North Star: "The Site-Office Document"**

This is a printed technical document taught to behave like a website. Everything is set on white paper, divided by hairlines rather than boxes, and interrupted at intervals by a solid navy band — the way a standards manual alternates body pages with section dividers. Nothing floats. Content blocks have a stroke and a ground; they do not have a shadow, because a capability list is not a physical object you could pick up. Depth exists only where something genuinely moves.

Density is the argument. The catalogue shows 108 named programmes and 75 named consultancy capabilities in full, in scannable rows with monospaced codes, instead of summarising them into three icon cards. That refusal is the system's centre of gravity: where a category site abstracts, this one enumerates, and the layout is tuned to make long enumerations legible — two- and three-column row grids, hairline separators, right-aligned counts, and a sticky filter bar so the list stays navigable at length.

The palette is not chosen, it is sampled: every hue is pulled from the client's logo lockup, and the four pillars (Health green, Safety blue, Environment orange, Training purple) do real work as a coding system rather than decoration. Crimson is the only action colour, and it is rationed. There is no photography anywhere on the site; the hero's process-plant elevation is authored inline SVG line art, and the illustrative register is strictly line, never fill.

**Key Characteristics:**
- Logo-sampled palette; navy ground bands, crimson action, four pillar hues as coding
- Archivo 800 display against Source Sans 3 body, Overpass Mono for codes and counts
- Hairlines and rules instead of card shadows on content
- 4px radius almost everywhere; near-square, document-like
- Enumeration over summary: full lists, monospaced codes, visible counts
- Authored line-art SVG only; no photography
- One authored motion moment (staggered reveal), reduced-motion honoured

## Colors

A palette sampled wholesale from the client's logo lockup: a cold navy ground, a single crimson action, and four saturated pillar hues that code the service lines.

### Primary
- **Crimson Action** (`{colors.crimson}`): The only colour that means "do something." Primary buttons, the current nav item and its 2px underline, the enquiry-count badge, arrow glyphs in the process chain, the quote rule, remove affordances, error borders, and the full-bleed CTA band ground. Its deeper pair (`{colors.crimson-dk}`) is hover and error text only.
- **Deep Navy Ink** (`{colors.ink}`): simultaneously the body text colour and the ground of every dark band — hero, interior page heads, `.section--ink`, and the footer. The same value doing both jobs is what makes the light and dark passages read as one document.

### Secondary — the four pillars
Applied as a *local* accent, never as a global theme: a `--c` custom property set inline on the block (`.track--*`, `.principle`, `.domain`, `.cat-group`), which component CSS reads as `var(--c, var(--safety))`. Blue is the fallback, so an uncoded block is a Safety block.
- **Health Green** (`{colors.health}`), **Safety Blue** (`{colors.safety}`), **Environment Orange** (`{colors.environ}`), **Training Purple** (`{colors.training}`): 3px top border on cards, 2px underline on catalogue group heads, the 56px underscore beneath a domain head, checklist bullets, principle dots, and the filled state of a picked programme row.
- **Environment Text Orange** (`{colors.environ-ink}`): the darkened substitute used whenever Environment orange would be *text* on white. Orange strokes; orange does not set type.
- **Leaf Green** (`{colors.leaf}`): the hero's second light wash, the terminal node of the stage rail, and tailored-list bullet rings. A closing/completion colour, distinct from Health.

A block's `--c` is not restricted to the four pillars — navy, crimson and leaf also appear as domain codes where seven domains outnumber four hues.

### Neutral
- **Paper** (`{colors.paper}`): the default ground for the page, cards, inputs, the header and the drawer.
- **Surface / Surface-2** (`{colors.surface}`, `{colors.surface-2}`): alternating section tint, row hover, drawer footer, empty state.
- **Line / Line-2** (`{colors.line}`, `{colors.line-2}`): the workhorses. Line separates rows and sections; Line-2 is the heavier stroke on interactive edges (inputs, chips, ghost buttons).
- **Muted / Muted-2** (`{colors.muted}`, `{colors.muted-2}`): secondary prose and metadata on white.
- **On-navy set** (`{colors.on-ink-mut}`, `{colors.on-ink-lede}`, `{colors.on-ink-chip}`, `{colors.rule-ink}`): the dark band's own greys and its 16%-white hairline. Never reuse `{colors.muted}` on navy.
- **On crimson** (`{colors.on-crimson-mut}`): the one muted text colour permitted on the crimson CTA band — a crimson-tinted blush, never a neutral grey.
- **Print ink** (`{colors.print-ink}`): the print stylesheet only, which drops every band to white paper and black type. The no-pure-black rule governs screen shadows, not paper.

### Named Rules
**The Sampled-Palette Rule.** Every hue traces to the logo lockup. A new colour is not invented; it is either an existing token or a legibility-corrected variant of one, and the correction is named as such (`environ-ink` for Environment orange as text).

**The One Action Rule.** Crimson is the site's only action colour. If an element is crimson it can be clicked, is currently selected, or has failed validation. Pillar colours never become buttons; crimson never becomes a category.

**The Local Accent Rule.** Pillar colour is set on the block via `--c` and read downstream as `var(--c, var(--safety))`. Never hard-code a pillar hue inside a component — it removes the block's ability to be recoloured.

**The On-Navy Lift Rule.** Saturated hues do not survive the navy ground unlifted. On dark bands the record numerals and pillar dots switch to their lifted tints (`#FF8FAE`, `#8FC0F5`, `#A5DE72`, `#6FD07F`, `#7FB6F0`, `#FFB25E`, `#C9A0F0`), and the hero's emphasis word uses amber `#FFC77A`. Light passage and dark passage each get their own version of the same colour.

## Typography

**Display Font:** Archivo (with Helvetica Neue, Arial fallback) — weights 500/600/700/800
**Body Font:** Source Sans 3 (with Segoe UI, system-ui fallback) — weights 400/600
**Label/Mono Font:** Overpass Mono (with ui-monospace, Consolas fallback) — weights 400/600

**Character:** Archivo at 800 with tight negative tracking gives headlines an engineered, compressed authority; Source Sans 3 underneath is plain and unhurried at 1.65 line-height, built to be read in quantity under site-office fluorescent light. Overpass Mono appears only where something is a code or a count — it is the system's evidence typeface.

### Hierarchy
- **Display** (800, `clamp(2.35rem, 4.4vw, 3.7rem)`, 1.06, `-0.028em`): page h1 only. Capped at 19–20ch with `text-wrap: balance`.
- **Display hero** (800, `clamp(2.2rem, 3.6vw, 3.05rem)`, 1.06, 28ch): the home hero's h1 only. A step below the interior Display because the hero headline is a full sentence rather than a phrase; it holds three lines at desktop width.
- **Headline** (800, `clamp(1.95rem, 3.5vw, 3rem)`, 1.06): section h2.
- **Headline sub** (800, `clamp(1.5rem, 2.4vw, 2rem)`, 1.06): an h2 that heads a sub-section inside a page — consultancy domain heads, the lead-service head, catalogue group heads. One step for one job.
- **Quote** (Archivo 600, `clamp(1.25rem, 2.2vw, 1.6rem)`, 1.28, `-0.02em`, 34ch): the pull quote behind a 1px left rule — stated goals and positioning lines on home, about, consultancy and training.
- **Title** (800, `clamp(1.2rem, 1.7vw, 1.5rem)`, 1.2, `-0.02em`): h3 — principles, stage-rail items, block subheads.
- **Subtitle** (700, `1.0625rem`, 1.3, `-0.01em`): h4 — card titles inside tracks and footer columns.
- **Body** (400, `1.0625rem`, 1.65): all prose. Paragraphs cap at 70ch; descriptive sublines run 34–52ch depending on column width.
- **Lede** (400, `clamp(1.125rem, 1.6vw, 1.3125rem)`, 1.58, muted, 64ch): the sentence under a heading. `<strong>` inside a lede returns to full ink at weight 600.
- **Label** (Archivo 700, `0.75rem`, `0.14em`, uppercase): `.rule-label`, footer column heads, credential labels, footer pillars. Sits above the content it names, usually over a hairline.
- **Numeral** (Archivo 800, `clamp(2.6rem, 5vw, 3.6rem)`, 0.94, `-0.04em`, tabular-nums): record-band figures and track counts. The scale claims (30+/110K+/80M+) are typography, not graphics.
- **Code** (Overpass Mono, `0.75–0.8125rem`, muted): programme codes, domain numbers, counts inside chips and the enquiry badge.
- **Block subhead** (800, `1.125rem`, 1.2, `-0.02em`): h3 inside a component rather than a section — stage-rail items, principle headings, the slide-over head.
- **UI** (Archivo 600–700, `0.9375rem`, `-0.005em`): the workhorse. Nav links, every button, card prose, footer links, catalogue rows, checklist and domain-list items, result counts, industry and chain pills. When a block is dense enough that body size would crowd it, it drops to this step — not to a step of its own.
- **UI small** (Archivo 700, `0.875rem`): compact controls and their metadata — `.btn--sm`, filter chips, the footer baseline, validation messages.
- **Micro** (`0.8125rem`): breadcrumbs, field hints, credential pills, the footer legal line, mono codes. The floor; nothing is set smaller except the `0.75rem` tracked Label.
- **Control** (`1rem`, body face): every text input, select and textarea. Form controls never drop below 1rem, so mobile browsers do not zoom on focus.
- **Numeral small** (800, `2.25rem`, `-0.04em`): the per-track programme counts (32 / 53 / 23), a half-scale echo of the record band.
- **Wordmark** (800, `2.9rem`, 0.95, `-0.04em`): the footer's typeset secondary lockup. Scoped as `.footer-brand .footer-word`, because a bare class loses to `.footer-brand p`.
- **Glyph** (`1.25rem`, line-height 1): every `×` affordance — search clear, enquiry remove, panel close. One size for one affordance.
- **Print body** (`11pt`): the print stylesheet only, where points are the correct unit.

### Named Rules
**The Evidence Mono Rule.** Overpass Mono is reserved for machine-ish facts — a programme code, a domain number, a count. It never sets a sentence, a label, or a heading.

**The Tight Display Rule.** Archivo headings run 700–800 with negative tracking (`-0.028em`, tightening to `-0.04em` on numerals) and line-height at or below 1.2. Display type is compressed; body type is not. Do not set a heading in Source Sans 3.

**The No-Near-Duplicate Rule.** Eleven steps, each at least 1px from its neighbour: `0.75 / 0.8125 / 0.875 / 0.9375 / 1 / 1.0625 / 1.125 / 1.25 / 2.25 / 2.9rem` plus the clamped display, lede and numeral ranges. Two sizes less than 1px apart are drift, not a system — if dense content needs to shrink, it drops a whole step rather than acquiring a private one.

**The Count-Is-Visible Rule.** Wherever a list is grouped, filtered or truncated, its length is stated in type next to its name ("Seven domains · 75 capabilities", "All 108"). The number is the product claim.

## Layout

A single centred measure, `width: min(1240px, 100% - gutter*2)`, with the gutter itself fluid (`clamp(1.25rem, 4vw, 2.5rem)`). Every page is a vertical stack of full-bleed sections whose only variables are ground (paper / surface tint / navy) and vertical padding (`clamp(4.5rem, 8vw, 7.5rem)`, or the tight `clamp(3rem, 5vw, 4.5rem)`). Rhythm inside a section runs on a small set of repeating steps: `0.68rem` list rows, `1.2–1.5rem` field and card gaps, `clamp(1.6rem, 3vw, 2.6rem)` block padding, `clamp(2.5rem, 4vw, 3.75rem)` between a section head and its body.

The header is sticky at 84px, and `scroll-padding-top: calc(84px + 1rem)` keeps anchored targets clear of it. The catalogue filter bar is a second sticky layer pinned directly beneath at `top: var(--header-h)`; on wide consultancy layouts the domain head becomes sticky at `header + 1.5rem` while its checklist scrolls past.

Breakpoints are content-driven and each does one job: `560px` (mobile compression — full-width buttons, flexed chips, 150px logo), `600/640px` (lists become two columns), `700px` (form and tailored list pair up), `760px` (tracks to three columns, principles to two), `820px` (record band to three columns), `860px` (CTA splits, footer to four columns), `900–940px` (two-col blocks, stage rail to two columns, contact grid), `1000px` (hero splits `1.06fr / .94fr`), `1060px` (catalogue to three columns), `1120px` (nav collapses to the drawer). Grids are asymmetric by preference — `1fr 1.05fr`, `1.35fr .75fr`, `1.5fr 1fr 1fr 1.2fr` — rather than an even split when the content is uneven.

A print stylesheet ships: chrome, filters, drawer and CTA are dropped, all navy grounds flip to white with black type, body at 11pt.

### Named Rules
**The Band Rule.** Vertical structure comes from alternating full-bleed grounds — paper, surface tint, navy — not from boxing content. A new section changes its ground and its padding; it does not get a bordered container around the whole thing.

**The Hairline Rule.** Separation is a 1px line in `{colors.line}` (or `{colors.rule-ink}` on navy). Rows, domains, contact blocks, footer bottom and section heads all divide this way. Heavier strokes are reserved and meaningful: 2px for a coded group head, 3px for a pillar-coded block edge, 1.5px for an interactive edge.

## Elevation & Depth

Hybrid, with a hard split by role. Content is flat: cards, lists, domain blocks, programme rows and the record band carry a 1px stroke, a tint, or a rule — never a shadow. Shadows exist only on surfaces that *move or overlay*: primary buttons (which lift on hover), the mobile nav drawer, and the enquiry slide-over panel. The distinction is the rule, not the absence. Depth in the flat layer comes from ground changes (paper → surface → navy), stroke weight, and the hero's two radial light washes.

### Shadow Vocabulary
- **Resting lift** (`box-shadow: 0 1px 2px rgba(14,31,56,.06), 0 2px 8px rgba(14,31,56,.05)`): the primary button at rest — just enough to read as pressable.
- **Hover lift** (`box-shadow: 0 2px 4px rgba(14,31,56,.05), 0 10px 26px rgba(14,31,56,.09)`): the primary button on hover, paired with `translateY(-1px)`.
- **Overlay** (`box-shadow: 0 4px 8px rgba(14,31,56,.06), 0 22px 50px rgba(14,31,56,.13)`): the mobile nav drawer dropping over page content.
- **Slide-over** (`box-shadow: -8px 0 24px rgba(14,31,56,.14)`): the enquiry panel entering from the right edge.
- **Scrims** (`rgba(14,31,56,.45)` for the enquiry panel, `rgba(14,31,56,.5)` for the open nav): navy at low alpha, never neutral black.

Every shadow is tinted with the ink navy (`rgba(14,31,56,…)`), never pure black.

### Named Rules
**The Moving-Surface Rule.** A shadow means the surface can move or sits above the page. Buttons, the nav drawer and the slide-over panel get one. A card, a list row, a domain block or a band does not — those use a 1px stroke and a ground change instead.

**The Inset-Selection Rule.** Selected state is drawn *inside* the box, not under it: a picked programme row uses `box-shadow: inset 0 0 0 2px var(--c, var(--safety))` with a transparent border, so selection never changes the row's footprint or the list's rhythm.

## Shapes

Near-square and document-flat. One radius does almost everything: 4px (`{rounded.default}`) on buttons, chips, inputs, programme rows, tag pills and the empty state. 2px (`{rounded.hairline}`) is the micro-radius for marks that are almost geometric — focus-ring corners, the current-nav underline, credential tags, principle dots, checklist bullets. Full circles (`{rounded.circle}`) appear only on small round tokens: the stage-rail numerals (2.75rem, `decimal-leading-zero` counters), the programme add button (26px), footer pillar dots, tailored-list bullet rings. The pill radius (`{rounded.pill}`) appears once, on the enquiry count badge.

Borders carry the form language. 1px is structural and separating; 1.5px marks an interactive edge (inputs, chips, ghost buttons — declared on the base `.btn` as `1.5px solid transparent` so hover never shifts layout); 2px underlines a coded group; 3px is the pillar-coded top or side border that assigns a block to a service line. Rules are directional and carry meaning: `border-top` opens a block, `border-bottom` closes a row, `border-left` marks a quotation, and a 56px × 3px bar under a domain head stands in for a divider.

Illustration is pure line: the hero's process-plant elevation is authored inline SVG at 1–2px strokes over dashed horizon rules, no fills, and no photography anywhere in the build.

## Components

### Buttons
- **Shape:** softly squared (4px), inline-flex with a `0.55rem` gap so an arrow glyph can sit inside the label.
- **Primary:** crimson ground, white Archivo 700 at `0.9375rem`, `0.9rem 1.5rem` padding, resting shadow.
- **Hover / Focus:** deepens to `{colors.crimson-dk}`, lifts `translateY(-1px)` into the hover shadow, and any `.btn__arrow` slides `translateX(3px)`. Focus is the global ring — `3px solid {colors.crimson}` at `3px` offset. All transitions run `.18s` on the house easing `cubic-bezier(.16,.84,.28,1)`.
- **Ghost:** paper ground, ink label, `{colors.line-2}` 1.5px edge; hover darkens the edge to ink and fills with surface tint.
- **On-ink:** transparent with a 42%-white edge, for navy grounds only; hover fills 10% white and whitens the edge.
- **Inverted (CTA band):** on the crimson band the primary button inverts to white ground with a crimson label, hovering to `#FFEAF0`.
- **Small:** `0.6rem 0.95rem` at `0.875rem`, used in the header bar.
- **Disabled:** 50% opacity, no lift, no shadow.

### Chips
- **Filter chip:** Archivo 700 `0.875rem`, paper ground, 1.5px `{colors.line-2}` edge, 4px radius, with a monospace count at 60% opacity. Hover darkens the edge to ink.
- **State:** `aria-pressed="true"` inverts the chip to solid ink with white type. Selection is a colour inversion, not a border change.
- **Static tag (industries):** the same silhouette without interaction — 1px edge, no hover; on navy the edge becomes `{colors.rule-ink}` and type `{colors.on-ink-chip}`.
- **Credential mark (`.cred-logos`):** the awarding bodies are shown as artwork, not set as type. Each logo ships as a PNG already matted on white and optically normalised to a common ~74px ink height, so six different aspect ratios read as one row. Rendered at `height: clamp(48px, 5vw, 64px)`, `width: auto`, 4px radius, and a single `rgba(14,31,56,.12)` hairline that defines the white tile on navy and on paper alike. The row sits beside its uppercase label on the hero rule and repeats on About.

### Cards / Containers
- **Corner Style:** 4px, or square where the block is a band rather than a card.
- **Background:** paper on tinted sections, transparent on paper sections.
- **Shadow Strategy:** none — see The Moving-Surface Rule. A card is a stroke plus a 3px pillar-coded top border.
- **Border:** 1px `{colors.line}` all round, plus the pillar-coded 3px top edge on service-line cards.
- **Internal Padding:** `1.5rem` for a track card, `clamp(1.6rem, 3vw, 2.6rem)` for the lead-service block.
- **Hover (linked cards only):** border darkens to ink and the card rises `translateY(-3px)` — motion without a shadow.

## Do's and Don'ts

### Do:
- **Do** separate with hairlines — 1px `{colors.line}` on paper, `{colors.rule-ink}` on navy — and reserve 2px/3px strokes for coded group heads and pillar-coded block edges.
- **Do** set pillar colour on the block as an inline `--c` and read it as `var(--c, var(--safety))` inside components.
- **Do** switch to the lifted on-navy tints and the on-navy grey set whenever content sits on an ink band.
- **Do** use `{colors.environ-ink}` whenever Environment orange needs to be text on white.
- **Do** state list length in type wherever a list is grouped or filtered.
- **Do** keep motion to the single staggered reveal (opacity + `translateY(22px)` + `blur(6px)`, `.7–.8s` on `cubic-bezier(.16,.84,.28,1)`, per-item delay via `--d`), gate it behind the `.js` class so content is visible without JS, and neutralise it under `prefers-reduced-motion`.
- **Do** keep form controls at `1rem` or larger and pair the `{colors.safety}` focus border with the global 3px crimson focus ring.
- **Do** scope footer-brand typography with descendant selectors (`.footer-brand p`, `.footer-brand .footer-word`); a bare class loses to `.footer-brand p` on specificity.

### Don't:
- **Don't** put a shadow on a content surface — cards, rows, domain blocks, bands. Shadows belong to buttons, the nav drawer and the slide-over only.
- **Don't** introduce a colour that isn't sampled from the logo or a named legibility correction of one.
- **Don't** let a pillar colour become an action, or crimson become a category.
- **Don't** use photography or filled illustration; illustration is authored line-art SVG.
- **Don't** set Overpass Mono on anything that isn't a code, a number or a count.
- **Don't** place the header logo image on the navy footer — its subtitle is black and its emblem navy, neither of which survives; use the typeset `.footer-word` lockup instead.
- **Don't** change a selected element's footprint; draw selection inset (`inset 0 0 0 2px`) so list rhythm holds.
- **Don't** exceed the radius vocabulary: 4px for controls and cards, 2px for micro-marks, full circles for small round tokens.
